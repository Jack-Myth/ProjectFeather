# Feather、Python 和 Lua 混合负载基准

在仓库根目录运行以下命令。Python 使用执行脚本的解释器，Feather 需要能加载 stdio 和 time 模块。Lua 使用标准 PUC-Lua。

```powershell
python benchmarks/mixed/compare.py --feather build/release/feather.exe --lua lua
```

## 2026-11-21 本机结果

Windows x64，当前工作区的 Feather Release、CPython 3.12.14、PUC-Lua 5.4.8。耗时单位为毫秒，倍数按耗时中位数相除。

| 负载 | Feather | Python | Lua | Feather / Python | Feather / Lua |
|---|---:|---:|---:|---:|---:|
| 4096 个整数的迭代归并排序 | 32.197 | 5.987 | 2.500 | 5.38 | 12.88 |
| 两条长度为 256 的布尔序列的编辑距离 | 53.611 | 8.550 | 3.250 | 6.27 | 16.50 |
| 256 个粒子更新 256 帧并在边界反弹 | 83.290 | 9.294 | 5.000 | 8.96 | 16.66 |

三份实现都从相同输入开始，包含数据构造、计算和结果汇总。排序返回按位置加权的和，编辑距离返回最少编辑次数，粒子返回包含每个粒子最终位置和速度的加权和。预期值分别用内置排序、递归记忆化编辑距离、周期反射公式独立核对。

本节数据来自数组下标仍为只读的版本，当时排序缓冲区和编辑距离的可写行使用数字键对象。只读输入序列和粒子列表使用数组。Python 使用 list 和带 `__slots__` 的粒子类，Lua 使用 table。Python 和 Lua 使用原生整数，Feather 使用 number，本组整数运算均在双精度可精确表示的范围内。

每种语言启动三个独立进程，轮换三种语言的启动顺序。每个进程按表中顺序循环四轮，每轮每项连续运行四次，记录平均单次耗时。首轮预热，余下共九个样本取中位数。每批检查最后一次的返回值。计时排除进程启动、脚本加载和输出。Feather 使用 time.Monotonic，Python 使用 perf_counter，Lua 使用 os.clock。Windows 上 Lua 的计时分辨率约为 1 ms，四次合计后，单次样本的粒度约为 0.25 ms。

## 局部对象字段指令（2026-11-21）

以 `faee869` 的 Release 为旧版，和新增字段指令的 Release 在同一台机器上跑相同脚本。共六组，每组交替先跑旧版或新版。下表为每个进程预热后的中位数再取六组中位数，变化列为同组耗时变化的中位数。三项混合负载均通过校验。

| 负载 | 旧版 ms | 新版 ms | 配对耗时变化 |
|---|---:|---:|---:|
| 归并排序 | 32.078 | 31.819 | −0.55% |
| 编辑距离 | 52.660 | 52.415 | −0.40% |
| 粒子更新 | 83.115 | 43.114 | −48.28% |
| 成员读写 | 44.889 | 17.571 | −60.83% |
| 局部累加 | 9.828 | 9.820 | −0.02% |
| 跨模块累加 | 10.064 | 10.005 | −0.84% |

在粒子的常见路径上，`p.x = p.x + p.vx` 从九次分派降到五次。解释器依次准备赋值目标、读两个字段、执行加法、写回并丢弃表达式结果。读写继续使用原来的成员哈希表。六组粒子更新的耗时降幅为 47.5% 到 48.6%。

另用旧版跨语言脚本各跑六组，每次循环 262,144 次，核对九个种子的结果。全局函数调用从 33.55 ms 增至 34.57 ms，六组均慢，配对中位数增加 3.2%。纯数值循环从 14.13 ms 增至 14.39 ms，配对中位数增加 3.2%，单组变化在 −6.5% 至 +9.3% 之间。数字键索引的配对中位数增加 0.6%。过期 native 对象的 GC 基准单独复测十二组，新旧中位数均为 0.004 ms。

同轮跨语言复测中，粒子更新耗时为 Feather 42.752 ms、CPython 3.12.14 9.213 ms、Lua 5.4.8 5.000 ms。

## 数组已有元素覆盖写入（2026-11-21）

当前脚本用 `Add` 初始化排序缓冲区和编辑距离的两行，再用下标覆盖已有元素。同一 Release 上交替运行数字键对象和数组两个版本，共四组，包含初始化成本。归并排序从 32.41 ms 到 33.84 ms，配对耗时增加 4.8%；编辑距离从 53.33 ms 到 53.06 ms，减少 0.7%。粒子代码在两个版本中相同，配对耗时相差 0.8%。所有结果通过校验。

独立跨语言复测（Feather / CPython / Lua，单位 ms）分别为归并排序 32.500 / 5.920 / 2.500，编辑距离 52.409 / 8.409 / 3.250，粒子更新 44.998 / 9.118 / 5.000。

## 局部数组整数下标指令（2026-11-21）

基线为 `e2ab764`。Windows x64 MSVC Release，原版三份混合负载脚本均未改动。独立跑六组成对测试，新版归并排序耗时下降 36.9%，编辑距离下降 48.5%，粒子更新下降 13.3%（同轮配对变化的中位数）。

随后轮换运行新旧 Feather、CPython 3.12.14 和 PUC-Lua 5.4.8。每种运行时四个进程，每个进程丢弃首批预热，按剩余十二个样本取中位数。各批结果均通过校验。

| 负载 | 旧 Feather ms | 新 Feather ms | Python ms | Lua ms | Feather / Python 旧 → 新 | Feather / Lua 旧 → 新 |
|---|---:|---:|---:|---:|---:|---:|
| 归并排序 | 32.535 | 20.630 | 5.942 | 2.500 | 5.48 → 3.47 | 13.01 → 8.25 |
| 编辑距离 | 52.478 | 26.695 | 8.554 | 3.250 | 6.14 → 3.12 | 16.15 → 8.21 |
| 粒子更新 | 44.778 | 39.034 | 9.350 | 5.000 | 4.79 → 4.17 | 8.96 → 7.81 |

跨模块累加有小幅退化：首轮六组配对慢 4.0%，独立复测十六组慢 3.6%（12/16 组慢，旧 10.008 ms、新 10.345 ms）。后者的局部累加和成员读写分别为 −1.1% 和 −0.6%，GC 的新旧中位数均为 0.004 ms。16、256、2048 个函数的模块加载配对变化分别为 +2.7%、−4.1%、−1.8%。另测六组纯数值循环、全局函数调用和数字键对象读取，分别为 +1.4%、约 0%、−1.0%，各项均有快有慢。
